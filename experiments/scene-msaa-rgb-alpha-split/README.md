# Separate RGB sharing from exact sample alpha

Status: private native V2 held; no adopted product/WASM gain.

The accepted four-sample material merge shades multiple triangle contributions within one pixel together only if uploaded albedo alpha is constant. Bistro has many OPAQUE materials with variable stored texture alpha, so most of its materials cannot use that path. The proposed experiment keeps the original sample winners, coverage and depth, shares expensive RGB lighting within a material/pixel, and reconstructs the original alpha separately. No neighboring pixels or previous frames are reused, and meshes/textures stay unchanged.

First measure native user-cycle profiles for BMW and Bistro after the accepted change. These are diagnostics, not wall-time performance gates. Candidate adoption requires balanced native AB/BA checks at 640×360 with four total threads, samples off/2×/4×, original alpha and depth checks, independent regression fixtures, sanitizers and actual WASM/SIMD128/browser validation.

Sources: own proposal based on the retained [material merge experiment](../scene-msaa-material-pixel-merge/README.md), the current `scene_shade_packet`/MSAA grouping in `libsoftgl/src/scene_visibility.c`, and canonical UV sources and clipping in `libsoftgl/src/geometry.inc`. The cycle profiler is copied from the [Full MSAA control recipe](../scene-full-msaa-control/validation/native-recipe/profile.py); it enables counters only after asset import and warm-up.

V1 restored lost alpha inside each pixel. V2 collects up to twelve distinct lost alpha contributors across a four-pixel RGB packet, reuses identical original winner/point alpha and evaluates the original albedo alpha in SIMD128. An unused shade-mask bit marks the extra work; compressed uniform winners are never read as materialized secondary IDs. Canonical raw/clipped UVs avoid recomputing discarded lighting attributes.

The independent 126-pair native contract passes, including nine intentional seam-color approximations, exact physical samples/alpha, reset, masks and fallback. Nine Bistro 4× views have byte-identical resolved and sample alpha and depth buffers; worst per-view RGB MAE is 2.0334 of 255, maximum channel change 137. Other full-model modes/assets were not independently quality-gated for adoption. Native ISA audits find no AVX/YMM/ZMM in both variants. No sanitizer or actual-WASM/browser validation was run.

V2 screen: Bistro −2.52%, BMW −10.23%, Sponza −0.33%, T-80 +2.19% frame time. The BMW control outlier is not an algorithm gain because its uploaded alpha is constant and does not use this restoration. A three-block Bistro-only repeat gives 54.7207→53.5818 ms (−2.08% time); all three selected pairs favor the candidate, but it is a small effect with an extra RGB approximation. One block contaminated by our own prototype build was automatically rejected at 1.32/1.00 foreign CPU cores and remains in the raw receipt. This was not overlapped into the later complete rebased-edge acceptance campaign. The method remains held while the equally small, exact-output edge gain is adopted.

Current V6 cycle profiles, retained as diagnostics: BMW 21.89% general MSAA raster, 10.37% small MSAA and 9.27% `scene_resolve` material shading; Bistro 26.14% `scene_resolve` material shading plus 3.95% scalar and 2.43% coherent cubemap sampling. The separate sample averaging routine `sg_msaa_resolve` accounts for only 1.34% in BMW and 0.33% in Bistro. These are user-cycle shares across inherited threads, not joined frame-time speedups. Profiles exclude import/warm-up and include 120 rotating frames.

Run `python3 archive_evidence.py` to verify the frozen source, raw selected/rejected timings, nine-view quality scope and cycle reports. No executable, texture pack or profiler binary is committed. Fresh reproduction uses the explicit V6 baseline: `prepare.py --baseline-revision cca5d8c --output-root NEW_ROOT`; measured V1/V2 recipes are retained separately under `validation/variants/`.

A separate follow-up could make the viewer's OPAQUE output alpha explicitly constant through ordinary GL combiner state, then share material shading without reconstructing irrelevant texture alpha. The [Khronos glTF 2.0 alpha-coverage specification](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc#alpha-coverage) requires OPAQUE output to ignore base-color alpha. This is a proposal, not this prototype's measured behavior: generic GL, MASK and BLEND must keep their configured alpha, and every renderer must receive the same new viewer state. RGB/coverage/depth comparisons and an independent Mesa combiner regression would precede performance acceptance.
