# Guarded affine sample-depth comparisons

Status: proposed next architecture trial; no implementation or measurement and no adoption.

The current [BMW cycle profile](../scene-msaa-rgb-alpha-split/validation/profile-bmw/candidate-report.txt) puts roughly 32% of cycles in general/small 4× rasterization, with additional winner-storage and capture costs. Sharing material RGB has already reduced shading, so another large BMW gain must address this work. Keep the four original sample positions and exact integer top-left coverage; propose a cheaper affine depth plane for rejection/acceptance of samples during an explicitly captured opaque scene.

Compute a conservative interval around the proposed depth, accounting for the current integer-to-float conversions, expression grouping, clamping and any recurrence drift. A comparison is decided cheaply only when incoming and stored intervals are strictly separated. Otherwise evaluate the existing exact expression for both candidates, including reconstructing the old winner's depth if it was stored provisionally. Preserve equality and original triangle order. Initial pre-scene framebuffer values are exact and have zero approximation interval. Alpha-tested materials and unsupported/unproved ranges retain the existing kernel.

After visibility is complete, reconstruct the original exact sample depths for final winners before any subsequent GL drawing or framebuffer observation. This may save depth work for rejected overdraw while paying exact reconstruction once per surviving winner. It requires storing or recovering original vertex depths and unbiased edges for clipped and unclipped canonical primitives; no stale geometry may survive the frame. Failures must restore both original buffers and hierarchical depth summaries. Hierarchical rejection must use conservative interval bounds until reconstruction is complete.

This is an own proposal grounded in the [existing sample-depth expression and coverage kernel](../../libsoftgl/src/raster_msaa_impl.h), [captured winner records and rollback](../../libsoftgl/src/scene_visibility.c), [hierarchical-depth margins](../../libsoftgl/src/raster_hz.h), and [independent edge-arithmetic fixtures](../scene-msaa-rebased-edges/arithmetic_contract.c). It is not a reduced sample count, neighboring-pixel shader, mesh LOD or temporal cache. A simpler approximate depth plane without a proven comparison guard does not meet this experiment's correctness target.

First freeze a private SIMD128 candidate and control at the committed parent. Use an independent exact-depth oracle with adjacent depth values, ties, gradients, reversed winding, clip/viewport boundaries, old ordinary draws, partially covered pixels, mixed materials, transparent follow-up draws and rollback. Prove the interval numerically before trusting it. Then compare original assets in balanced native AB/BA at 640×360 with caller plus three helpers and off/2×/4×. Require exact final physical depth/coverage and no additional RGB/alpha changes, sanitizer and actual WASM/browser gates. Retain unsuccessful trials. There is no predicted FPS gain until measured.
