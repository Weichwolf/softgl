# Preserve raw sample edges across raster pixels

Status: held exact SIMD128 prototypes; no confirmed useful gain, no adoption.

The accepted rebased 4× kernel maintains coarse signed-32 coverage edges, then reconstructs raw sample edges for every covered pixel before float conversion. Maintain two additional raw signed-32 edge vectors instead. Their additions wrap modulo 2^32 through SSE/WASM integer SIMD. The existing admission proof bounds all raw samples of a covered pixel to signed-32, so the reconstructed bits equal the original integer edges before conversion. Uncovered raw values may wrap and are never interpreted as depth or coverage. Keep the coarse vectors for exact top-left coverage and span rejection, and retain the original depth grouping, clamp, physical sample stores and shading points.

The second variant also maintains biased vector edges in the small ≤8×8 kernel, replacing repeated scalar broadcasts. Its original extent proof bounds the complete rectangle and sample edges; scalar shading edges remain unchanged. These are raster arithmetic recurrences, not floating depth recurrences, larger SIMD, lower sample counts or reduced-resolution shading.

The third variant keeps the original small kernel and also takes the larger kernel's unchanged shading point directly from the raw recurrence. Partial pixels select the original first covered sample. Fully passed pixels add the precomputed integer delta from sample zero to the original pixel center. This removes the remaining per-pixel coarse corrections and reconstruction; all selected raw edges are within the existing signed-32 bound and all center arithmetic uses signed-64.

This is an own proposal based on [the accepted rebased edge kernel](../../libsoftgl/src/scene_visibility.c), [its independent arithmetic fixtures](../scene-msaa-rebased-edges/README.md) and [the measured BMW/Sponza cycle profiles](../scene-msaa-guarded-depth-planes/README.md). Freeze the actual parent and recipe, link independent contracts against the measured library, audit SIMD128 and compare identical original assets/cameras at 640×360 with caller plus three helpers. Require a useful repeated off/2×/4× native gain before full sanitizer/WASM/browser adoption gates.

All three frozen variants pass the four independent measured-library contracts (material sharing, canonical positions, mixed MSAA/rollback and serial/worker planes) and the SIMD128/no-AVX disassembly audit. V3 additionally preserves all exported RGBA/depth/stencil/sample-plane hashes in 108 original-model views at off/2×/4×. V1 has no asset timing or full-model quality claim.

V2 and V3 each have one balanced all-scene 4× AB/BA screen, 60 warmup/30 rotating frames, 640×360/four total threads. V2 changes time Bistro/Sponza/BMW/T-80 +0.82/+26.21/−10.51/−0.18%; V3 +0.67/+23.38/+0.18/−3.16%. V2's BMW result includes a 20.303 ms control against 16.239 ms in the other direction; the candidate remains 16.163/16.539 ms, close to other controls. V3's T-80 result also includes a slower first control. These observations establish no adopted gain.

Sponza's V3 paired-resident screen is 33.233→41.002 ms. A separate three-block **fresh-process-per-request** diagnostic, preserving the same resident driver, asset, camera, 60 warmup/30 timed frames and four-thread budget, gives 32.934→33.615 ms (+2.07%). Import is measured separately and excluded from the driver's timed frames. All endpoint planes are identical and every whole block passes the ≤0.1 foreign CPU-core limit. The difference between launch procedures remains unexplained; the additional diagnostic does not silently replace the established paired-resident acceptance. There is no demonstrated improvement under either procedure.
