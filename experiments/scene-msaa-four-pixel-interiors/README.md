# Four adjacent interior pixels with affine sample depths

Status: two held native approximation trials; no useful all-scene screen gain or product adoption.

The accepted 4× kernel fills SIMD128 lanes with four samples of one pixel. For a run of four pixels that every triangle edge proves fully covered at all sixteen original sample positions, try filling those lanes with four adjacent pixels instead. Evaluate one affine depth vector and add the four precomputed sample offsets, compare against the sixteen physical old depths after a 4×4 transpose, then retain each pixel's actual four-sample passing mask, original center/first-sample shading point and winner. Border pixels and masked materials use the current kernel. This computes fresh current-frame visibility; it changes neither shading resolution nor meshes, textures or sample count.

The affine expression and sample offsets change float rounding and can change very close depth winners. Assess covered-depth masks, alpha/stencil, depth differences and actual RGB errors explicitly against fresh parent frames. A first prototype is not an exact GL replacement or a claim of zero error. Preserve the generic GL path and existing test tolerances. Native and WASM remain SIMD128, with no new buffers or frame history.

This is an own SIMD lane-layout proposal based on [the existing rebased raster kernel and physical sample store](../../libsoftgl/src/scene_visibility.c), the [failed direct-plane controls](../scene-msaa-guarded-depth-planes/README.md) and [exact integer recurrences](../scene-msaa-raw-edge-recurrence/README.md). Unlike simply replacing four-sample arithmetic with a plane, it amortizes that plane across four output pixels. All performance claims require complete native rendering of the original four scenes/cameras at 640×360, four total threads, balanced repeated off/2×/4× measurements, independently checked geometry/materials, sanitizer and actual SIMD128 WASM/browser gates before adoption.

V1 embeds the batch body in the rebased raster loop. V2 moves the same arithmetic to a `noinline` helper and materializes its extra parameters once per triangle, so they need not stay live throughout the ordinary loop. This tests an implementation tradeoff; the timing alone does not prove that register spills caused a difference. Both actual libraries and timed drivers pass the SIMD128/no-AVX disassembly audit.

Both variants assess **36 original-model 4× views** against fresh frozen parent images. All covered-depth masks and stencil remain exact, and the maximum depth change is 1.79e-7. Worst mean RGB errors, in byte units, are Bistro 0.002935/255, Sponza 0.0000883/255, BMW 0.0000116/255 and T-80 zero. Sparse local maxima are 113/255, 23/255, 3/255 and zero; Bistro's worst fraction over 8/255 is 0.01085%. These are sparse changed depth winners, not a global ≤1/255 guarantee. Alpha is not independently exported by this assessment. Every exported candidate plane hash and assessment value matches between V1 and V2 in these views.

The unchanged measured-library material-sharing fixture passes 90 paired frames in V2. The canonical-position fixture then fails its **strict resolved-depth byte comparison**, as expected from the deliberate arithmetic change; its signal/status and exact failing assertion are retained. This is not reported as a passing native correctness gate, and no repository fixture or tolerance is changed. Remaining full contracts, sanitizer, actual WASM/browser and adoption checks were not pursued without a useful gain.

Each variant has one complete all-scene 4× AB/BA screen with sixty warmup/thirty rotating timed frames per request, 640×360/four total threads and identical packs/cameras. V1 changes Bistro/Sponza/BMW/T-80 frame time +5.60/+28.86/+2.45/+8.25%; V2 +3.48/+0.60/+5.11/+4.82%. No useful gain is established. The large V1 Sponza paired-resident observation is retained; [other trial launch diagnostics](../scene-msaa-raw-edge-recurrence/README.md) show why its full magnitude cannot automatically be assigned to arithmetic. No confirmation campaign or fresh three-renderer comparison is claimed.

An explicitly instrumented copy counts two actual views (0°/160°), with both batch entries and all candidate visits in the specialized small/rebased kernels. Batch visits include depth-rejected pixels and overdraw; they are not distinct output pixels. BMW reaches 50,380/72,036 of 464,358/722,935 visits (**10.85/9.96%**); T-80 29,940/45,460 of 335,827/472,962 (**8.92/9.61%**); Sponza 231,248/235,136 of 1,177,245/1,183,641 (**19.64/19.87%**); Bistro 275,928/279,868 of 1,858,151/1,851,572 (**14.85/15.11%**). The ordinary general kernel is outside that denominator. Census timings are discarded. Extra counters/drivers are frozen separately and never supply an FPS claim. These finite visits limit this first admission rule's reach; they do not prove other lane-layout designs impossible.

Parent is `52aff7b`, Clang 22.1.8, original assets/full shading/no frame history.
